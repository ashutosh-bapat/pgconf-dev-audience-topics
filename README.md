# pgconf-dev-audience-topics

Community-requested talk topics for [pgconf.dev](https://pgconf.dev).

This repository is intended to host **GitHub Discussions** where attendees can propose, discuss, and upvote topics they want to see.

## Current status

Repository is created. Next steps are to launch and validate Discussions.

## 1) Enable GitHub Discussions

1. Open repository **Settings**.
2. Enable **Discussions**.
3. Confirm that the **Discussions** tab appears.

## 2) Create initial categories

Start with only these categories:

- **Announcements** (organizers-only updates)
- **Topic Requests** (audience-submitted talk ideas)

Keep categories minimal at launch; add more only after usage grows.

## 3) Post initial welcome / announcement discussion

In **Announcements**, create and pin a post such as:

**Title:** Welcome: Suggest topics for pgconf.dev

**Body:**
- This board collects audience-requested talk topics.
- Create one discussion per topic idea in **Topic Requests**.
- Upvotes and comments signal interest, but do not guarantee selection.
- Final scheduling depends on speaker availability, program balance, and conference goals.
- If your topic is selected, organizers may reach out to potential speakers.

## 4) Link from pgconf.dev

Add a visible link from pgconf.dev (for example in the CFP/topic suggestion area) to:

[`./discussions`](./discussions)

Suggested site copy:

> Have a talk topic idea? Propose and upvote topics in our GitHub Discussions board.

## 5) Seed initial topic discussions

Create 5-10 starter threads in **Topic Requests** to model good submissions.

Use a consistent format:
- **Topic title**
- **Why this matters to PostgreSQL users/developers**
- **Target audience** (beginner/intermediate/advanced)
- **Suggested speaker(s)** (optional)
- **Related links** (optional)

## 6) Validate end-to-end workflow

Run this checklist after setup:

- [ ] Visitor can open the Discussions tab without permissions issues.
- [ ] Visitor can create a new discussion in **Topic Requests**.
- [ ] Upvoting and commenting work.
- [ ] Announcement post is pinned and visible.
- [ ] pgconf.dev link opens the Discussions board correctly.
- [ ] Organizers can triage duplicates and mark shortlisted topics.

## Operating notes

- Start simple; avoid over-automation initially.
- Revisit category structure after collecting real usage feedback.
- Keep moderation lightweight and focused on constructive, on-topic requests.
