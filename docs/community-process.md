# Community-requested talks workflow

This document describes the public workflow used to gather and review community-requested talk topics for pgconf.dev.

## 1) Topic solicitation

- Audience members submit topic ideas through GitHub Discussions in this repository.
- Community members can upvote and comment to show demand, add use cases, and refine scope.
- Participants are encouraged to check for existing discussions before posting and add support to the existing thread when possible.

## 2) Organizer review

- Organizers periodically review requests, with extra attention to topics that show strong and consistent community support.
- Review includes discussion quality, relevance to pgconf.dev attendees, and practical fit for the event.
- Duplicate discussions may be consolidated so community support is visible in one place.

## 3) Speaker invitation path

- For selected high-interest topics, organizers may invite potential speakers to submit through pgconf.dev's standard proposal process.
- Invitations help surface promising topics but do not bypass normal proposal requirements.

## 4) Program caveats

Highly supported topics may still not appear in the final program. Selection depends on multiple factors, including:

- program balance across tracks and skill levels
- speaker availability and willingness to present
- talk quality and conference fit
- scheduling constraints and overall program composition

Community input is valuable and actively reviewed, but voting is one signal among several used to build the final conference schedule.
